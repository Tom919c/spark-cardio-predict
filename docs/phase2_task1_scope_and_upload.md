# 第二阶段任务一：机构端区域分析与数据上传

## 一、任务目标

本阶段首先优化机构端页面，并增加机构人员上传数据进行分析的能力。

当前页面固定展示全国地图，但项目实际使用的是成都市居民数据。后续地图必须根据数据覆盖范围动态决定：

- 成都市数据：展示成都市区县风险分布；
- 单个区的数据：不展示完整成都市地图，改为社区排名或统计图；
- 多城市或多省份数据：根据覆盖范围展示相应层级地图；
- 没有边界数据时：使用排名表或柱状图，不强行绘制地图。

## 二、区域分析方案

后端根据上传数据中的省份、城市、区县或社区字段判断分析范围，返回区域层级和聚合结果。前端根据返回的层级选择地图或普通统计图，不能把全国地图写死在页面中。

当前成都仿真数据包含 district 字段，第一版优先制作成都区县地图。地图资源建议放在项目本地，保证没有网络时也能正常显示。

地图中的风险值表示区域聚合指标，只用于区域之间比较，不直接表示居民个人的医学发病概率。

## 三、数据上传方案

第一版先支持 CSV 文件。上传后按以下流程处理：

上传文件 -> 字段检查 -> 数据预览 -> 数据质量校验 -> 执行分析 -> 展示结果

第一版上传数据只用于群体统计和页面展示，不自动覆盖正式模型，也不自动触发模型重训。

群体分析数据至少应包含年龄、BMI、区域字段，以及高血压、糖尿病、胆固醇、吸烟和运动等危险因素。若包含 label_heart 和 label_stroke，可以生成标签统计和随访名单；没有标签时只能做人口和危险因素分析。

后续可以增加批量个人评估，但它应与群体分析分开，避免把统计数据误当成个人预测数据。

## 四、联网能力

系统可以支持联网，但第一版不应该依赖网络才能运行。

适合优先支持的联网功能：

- 在线加载地图资源；
- 连接机构内部数据库；
- 将大文件分析任务交给远程 Spark 服务；
- 后续接入经过审核的知识库服务。

调用公网大模型或外部医疗数据平台的复杂度和风险较高，暂时不作为任务一的必需功能。项目应保留本地地图、本地模型和本地规则建议，网络不可用时仍然可以完成核心分析。

## 五、五人分工

### 组长

负责总体设计、接口契约、任务协调、代码审核、集成测试和最终验收。组长不再负责把所有成员的代码最后集中重构。

### 成员一：数据工程和 Spark

负责区域字段识别、区域聚合、成都区县数据整理和 Spark 分析脚本。

### 成员二：机器学习

负责上传数据的字段校验、批量预测方案、模型评估和后续 What-if 模拟的核心逻辑。

### 成员三：后端

负责文件上传、数据集状态、数据校验、分析任务和结果接口。

### 成员四：前端

负责上传页面、任务状态展示、动态地图、区域排名和页面联调。

## 六、开发顺序

1. 组长先确定区域数据格式、接口返回结构和验收样例。
2. 数据成员准备成都区县聚合结果和测试数据。
3. 后端成员完成上传、预览、校验和分析接口。
4. 前端成员根据固定接口开发上传页面和动态区域展示。
5. 机器学习成员补充批量分析和 What-if 方案，不直接修改前端。
6. 所有功能合并到 chenquan 分支，通过测试后再进入 main。

## 七、第一轮验收标准

- 成都数据不再展示全国地图；
- 单一区域数据能够降级为排名或统计图；
- CSV 可以上传、预览、校验并完成群体分析；
- 上传失败和数据格式错误有明确提示；
- 上传数据不会覆盖第一阶段正式模型；
- 没有网络时，本地核心功能仍然可以运行；
- 每个成员只修改自己负责的文件范围，并提供对应测试。

任务一暂时不实现公网大模型、真实时间趋势预测和模型 Stacking。
