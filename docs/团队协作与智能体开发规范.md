# 团队协作与智能体开发规范

## 1. 文档目的

本规范是 CardioSpark 后续开发的统一执行标准。所有成员和智能体都必须遵守项目边界、目录职责、分支流程和测试要求，避免重复开发、路径混乱和未经审核的代码进入主分支。

## 2. 当前项目基线

- 阶段一只实现两个独立风险模型：`label_heart` 心脏事件、`label_stroke` 脑卒中。
- 两个模型均为独立的随机森林模型，不使用三分类模型，也不扩展其他疾病模型。
- 阶段一模型已在成员本地 Conda 环境完成一次正式训练；重新训练或发布前仍需负责人审核模型指标与数据版本。
- B 端用于成都市仿真人口群体分析，C 端用于个人双风险评估。
- `chenquan` 是当前团队集成开发分支，`main` 只存放负责人审核确认后的版本。

## 3. 运行环境边界

| 环境 | 用途 | 约束 |
| --- | --- | --- |
| Windows 11 + 成员自定义 Conda 环境 | Flask、前端、API 调试、pytest | 默认使用 `DATA_MODE=local` |
| WSL2 Ubuntu 22.04 | Hadoop/Spark 伪分布式作业 | 需要单独 clone，配置 Linux 路径 |
| VMware Linux | 组员可用的 Hadoop/Spark 伪分布式环境 | 与 WSL2 使用相同脚本和配置规则 |

- Windows、WSL2、VMware 不共享同一个工作目录运行；每个环境分别 clone 仓库。
- 代码中的 Windows、WSL2、VMware 路径必须通过 `.env` 或配置项提供，禁止写入个人绝对路径。
- Windows 运行 Flask 和测试时不要求 Hadoop/Spark 已启动。
- 只有需要运行 Spark 作业时，才在 WSL2 或 VMware 中配置 Hadoop/Spark。

## 4. 目录职责

```text
app.py                 Flask 启动入口
config/                环境配置和运行参数
src/controllers/       HTTP 路由和请求响应适配
src/services/          业务服务和数据编排
src/ml/                 特征工程、训练、预测、评估、模型注册
src/spark_jobs/        Hadoop/Spark 伪分布式作业
templates/              B/C 端页面模板
static/                 页面静态资源
scripts/                数据准备、HDFS 上传、Spark 启动作业脚本
tests/                  自动化测试
docs/                   公开项目说明和开发规范
data/                   本地数据、模型和运行产物，不提交 Git
```

逻辑数据分层与本地目录映射如下：

- ODS：`data/raw/source_dataset/`，原始数据，只读保存，不直接用于页面接口。
- DWD：`data/raw/CVD_Standard_DWD.csv`，清洗后的标准双标签数据，用于特征工程和模型训练。
- DWS：`data/raw/chengdu_resident_health_simulated.csv`，成都市居民仿真数据，用于 B 端群体分析和重点筛查。
- ADS：`data/models/` 与 `data/features/`，模型、模型清单和服务特征产物。

当前仓库保留 `data/raw` 作为本地落盘目录，以兼容已有数据和 Windows 开箱运行；逻辑层名仍按 ODS/DWD/DWS/ADS 使用。

新增数据或模型时，先判断所属数据层，再放入对应目录；不要在项目根目录新增临时数据目录。

## 5. 文档规则

- `docs/` 保存需要随代码共享的公开说明
- 修改代码涉及接口、目录、数据字段或运行方式时，必须同步修改对应 `docs/` 文档。
- 文档只保留当前有效规则、必要命令和验收标准；过期方案直接修订或删除，不重复堆叠历史说明。
- 不确定某项规则时，以 `mydocs/项目方案.md` 和负责人最新确认结果为准，并在修改说明中记录假设。

## 6. Git 协作规则

### 分支

- `main`：审核发布分支，禁止直接开发和直接提交。
- `chenquan`：当前团队集成分支，用于负责人整合和阶段验收。
- 其他成员使用自己的开发分支，完成后提交合并请求或交由负责人合并到 `chenquan`。
- 合并前必须说明修改范围、测试结果、数据依赖和剩余风险。

### 提交


- 一次提交只解决一个明确主题，避免把格式化、重构和功能混在一起。
- 提交前检查 `git diff` 和 `git status`，确认没有误改、临时文件或本机配置。
- 禁止提交 `data/`、`mydocs/`、`.env`、模型文件、日志、缓存、IDE 配置和个人路径。
- 不得使用强制推送覆盖他人分支，不得擅自修改或回滚他人的未合并工作。

## 7. 智能体开发流程

每次让智能体修改代码，都必须按以下顺序执行：

1. 先读取 `mydocs/项目方案.md`、相关 `docs/`、目标模块和测试文件。
2. 查看当前分支、工作区状态和目标文件的现有修改，不能覆盖未确认的团队成果。
3. 把任务拆成一个明确主题，先说明修改范围、影响文件和验证方式。
4. 复用现有配置、服务和工具函数；没有必要时不新增抽象、不移动目录、不批量重命名。
5. 修改完成后补充或更新对应测试和文档，中文注释只解释业务规则、边界条件或复杂逻辑。
6. 运行与改动相关的最小测试集，再根据影响范围运行完整测试。
7. 检查路径、接口返回结构、异常处理和 Git 差异，确认没有训练产物或临时文件进入工作区。
8. 汇报变更文件、测试命令及结果、未完成事项和需要负责人决策的问题。

智能体未经负责人明确授权，不得执行以下操作：

- 大范围重构目录或删除旧文件。
- 修改阶段一模型目标、核心字段和对外接口契约。
- 执行正式模型训练、覆盖模型清单或删除已审核模型。
- 修改 `main`、推送远程、合并分支或处理与当前任务无关的冲突。
- 同时修改多个成员负责的核心文件。

### 智能体提示词模板

```text
任务：<一句话说明唯一目标>
背景：<对应项目方案、业务场景或问题现象>
允许修改：<文件或目录>
禁止修改：<文件、目录和操作>
验收标准：<接口、页面、测试或文档结果>
运行限制：不要正式训练，不要提交或推送；按项目当前环境执行。
完成后汇报：修改文件、关键变更、测试命令及结果、剩余风险。
```

## 8. 代码规范

### Python、Flask 和服务层

- 路由只负责参数校验、调用服务和组织响应；业务逻辑放在 `src/services/`。
- 模型训练、预测、特征处理和模型注册放在 `src/ml/`，不要写进路由函数。
- 所有文件路径从 `config/settings.py` 或环境变量获取，禁止硬编码本机路径。
- API 保持统一响应结构：`success`、`message`、`data`。
- 对缺少数据、模型未训练、字段缺失和格式错误返回清晰错误，不暴露堆栈和本机路径。
- 函数保持单一职责；公共函数补充类型标注，复杂业务规则添加简短中文注释。

### Spark 作业

- Spark 作业只处理数据计算和落盘，不直接依赖 Flask 请求上下文。
- HDFS 地址、用户名、输入输出目录和 `spark-submit` 路径统一从 `.env` 或命令行参数读取。
- 伪分布式作业必须支持重复执行，输出目录已存在时要有明确处理策略。
- 运行前先校验输入路径、字段和 Spark 环境；失败时输出可定位的错误信息。

### 前端

- 保留现有 B 端和 C 端页面的主要视觉结构，只做必要的 API 接入和字段适配。
- 页面数据全部来自 Flask API，不在页面中保留与正式接口冲突的 Mock 数据。
- API 返回空数据、失败或模型未就绪时，要显示明确状态，不直接调用未定义字段的 `map` 等方法。
- 页面脚本按页面职责组织，重复请求和格式化逻辑优先抽取为小型公共函数。

## 9. 数据、配置和模型管理

- 数据文件默认不进入 Git；新成员根据数据说明准备本地 `data/` 目录。
- `.env.example` 只保存变量名和示例值；个人 `.env` 不得提交。
- 训练数据必须先确认字段与 `docs/data_dictionary.md` 一致，再进入训练流程。
- 阶段一训练只能生成心脏事件和脑卒中两个模型，并由模型注册表统一记录。
- 训练前必须确认随机种子、特征列、标签列、数据版本和评估指标；训练后保存可复现记录。
- 未经负责人验收的模型只能放在本地，不得作为页面默认模型发布。

## 10. 测试与交付检查

代码修改至少在本机已配置的项目环境中执行：

```powershell
conda activate <your-conda-environment>
python -m pytest -q
```

涉及 Flask 或页面时，还要执行：

```powershell
python app.py
```

`<your-conda-environment>` 仅为占位符，各成员替换为自己的环境名；不要把个人环境名写入项目文档、脚本或提交信息。

并检查：

1. `GET /`、`/dashboard`、`/risk-report` 可以打开。
2. `GET /health` 返回成功。
3. 数据接口在数据存在、为空和路径错误时都有明确结果。
4. 模型未训练时，页面和预测接口给出可理解提示。
5. 模型就绪后，预测结果同时包含心脏事件、脑卒中概率和整体五级风险。
6. B 端统计和随访列表在空数据时不会触发前端异常。

涉及 Spark 时，在对应 Linux 环境补充执行：

```bash
./scripts/start_spark_jobs.sh <hdfs-input-file>
```

交付前必须确认：

- 测试通过，或明确说明失败原因和影响范围。
- 文档、接口字段和实际代码一致。
- `git diff` 中没有无关改动、本机路径、密钥、数据和模型产物。
- 已列出运行环境、配置项、数据依赖和后续风险。

## 11. 问题反馈格式

```text
问题：<现象>
环境：Windows / WSL2 / VMware，Python 和 Spark 版本
复现：<命令或请求>
日志：<关键错误，不粘贴无关完整日志>
已检查：<数据、配置、接口或分支状态>
期望：<正确结果>
```

发现会影响其他成员的结构、接口、数据字段或模型结果时，先停止扩散修改，通知负责人确认后再继续。
